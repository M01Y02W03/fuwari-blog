# Hosts 本地域名解析配置（Windows & Linux & macOS）

在企业内网开发、测试环境部署过程中，经常需要将某些内部域名直接解析到指定服务器 IP，而不依赖公司 DNS 服务器。

## 1.什么是 Hosts 文件

Hosts 文件本质上是一个**本地静态域名解析表**。

当访问：

```text
git.example.com
```

系统会优先查询 Hosts 文件：

```text
192.168.10.100    git.example.com
```

如果存在对应记录，则直接返回 IP，不再向 DNS 服务器发起查询。

解析顺序通常为：

```text
浏览器缓存
    ↓
系统DNS缓存
    ↓
Hosts文件
    ↓
本地DNS服务器
    ↓
公网DNS服务器
```

# Windows 配置 Hosts

## 1. Hosts 文件位置

```text
C:\Windows\System32\drivers\etc\hosts
```

### 使用管理员权限打开

方法一：

```text
开始菜单
    ↓
记事本（右键）
    ↓
以管理员身份运行
```

然后打开：

```text
C:\Windows\System32\drivers\etc\hosts
```

---

## 2. 添加解析记录

例如：

```text
# 公司内网服务
192.168.10.100 git.example.com
192.168.10.100 nexus.example.com
192.168.10.100 dev.example.com

# 测试环境
192.168.20.50 test-api.example.com
```

保存即可。

---

## 3. 刷新 DNS 缓存

管理员 CMD：

```cmd
ipconfig /flushdns
```

成功提示：

```text
Successfully flushed the DNS Resolver Cache.
```

---

## 4. 验证解析

```cmd
ping git.example.com
```

或者：

```cmd
nslookup git.example.com
```

也可以：

```cmd
curl http://git.example.com
```

---

# Linux 配置 Hosts

## 1. Hosts 文件位置

```bash
/etc/hosts
```

---

## 2. 编辑 Hosts

Ubuntu / Debian：

```bash
sudo vim /etc/hosts
```

或者：

```bash
sudo nano /etc/hosts
```

添加：

```text
# 公司内网服务
192.168.10.100 git.example.com
192.168.10.100 nexus.example.com
192.168.10.100 dev.example.com

# 测试环境
192.168.20.50 test-api.example.com
```

保存退出。

---

## 3. 刷新 DNS 缓存

### Ubuntu（systemd-resolved）

查看状态：

```bash
systemctl status systemd-resolved
```

刷新缓存：

```bash
sudo resolvectl flush-caches
```

或者：

```bash
sudo systemd-resolve --flush-caches
```

---

### CentOS / Rocky / AlmaLinux

如果使用：

```bash
nscd
```

则执行：

```bash
sudo systemctl restart nscd
```

如果使用：

```bash
dnsmasq
```

则执行：

```bash
sudo systemctl restart dnsmasq
```

---

## 4. 验证解析

```bash
ping git.example.com
```

```bash
curl http://git.example.com
```

```bash
getent hosts git.example.com
```

输出类似：

```text
192.168.10.100 git.example.com
```

表示解析成功。

# macOS 配置 Hosts

## 1. Hosts 文件位置

```bash
/etc/hosts
```

---

## 2. 编辑 Hosts

```bash
sudo vim /etc/hosts
```

添加：

```text
# 公司内网服务
192.168.10.100 git.example.com
192.168.10.100 nexus.example.com
192.168.10.100 dev.example.com

# 测试环境
192.168.20.50 test-api.example.com
```

保存退出。

---

## 3. 刷新 DNS 缓存

### macOS Ventura / Sonoma

```bash
sudo dscacheutil -flushcache
sudo killall -HUP mDNSResponder
```

执行后不会有输出，属于正常现象。

---

## 4. 验证解析

```bash
ping git.example.com
```

```bash
curl http://git.example.com
```

查看实际解析结果：

```bash
dscacheutil -q host -a name git.example.com
```

示例输出：

```text
name: git.example.com
ip_address: 192.168.10.100
```

# 五、常见问题排查

## 1. Hosts 修改后不生效

检查：

```bash
ping 域名
```

是否仍解析到旧 IP。

原因可能：

* DNS 缓存未刷新
* 浏览器缓存
* VPN 覆盖 DNS
* Hosts 格式错误

正确格式：

```text
IP地址 域名
```

例如：

```text
192.168.10.100 git.example.com
```

错误示例：

```text
192.168.10.100=git.example.com
```

---

## 2. 一个 IP 对应多个域名

可以写成：

```text
192.168.10.100 git.example.com
192.168.10.100 nexus.example.com
192.168.10.100 dev.example.com
```

也可以：

```text
192.168.10.100 git.example.com nexus.example.com dev.example.com
```

推荐第一种，可读性更好。

---

## 3. 一个域名切换测试环境

生产环境：

```text
10.10.10.10 api.example.com
```

测试环境：

```text
10.10.20.20 api.example.com
```

直接修改 Hosts 后刷新缓存即可完成环境切换，无需修改代码。
